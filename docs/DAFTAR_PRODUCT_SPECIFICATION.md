# DAFTAR — Product Specification / المواصفة المنتجية

## 1. الرؤية

**DAFTAR — دفتر**: منصة SaaS تجارية متكاملة تجعل إدارة أعمال التاجر "بسيطة جدًا" من الخارج و"قوية جدًا" من الداخل.

- الشعار: **إدارة أعمالك .. ببساطة** / *Business Grows Simpler*.
- العقيدة: Simple outside. Powerful inside. Premium everywhere. Correct by design. Safe to change. Zero silent errors.

## 2. الأسواق والجمهور

- الأسواق الأساسية: فلسطين، الأردن، لبنان، سوريا، تركيا (قابلة للتوسع للخليج والعالم العربي).
- اللغات: العربية (RTL أصلي)، الإنجليزية والتركية (LTR) — كلها لغات من الدرجة الأولى.
- العملات: ILS, JOD, LBP, SYP, TRY, USD, EUR.

## 3. الشخصيات المستخدمة (Personas)

| الشخصية | الوصف | أهم احتياجاته |
|---|---|---|
| التاجر/المالك (Ahmad) | صاحب متجر صغير/متوسط، غير تقني وغير محاسبي؛ **قد يدير أكثر من نشاط (Business) بحساب واحد** — كل نشاط بدولته وعملته ودفاتره المستقلة وتبديل سلس بينها | يبيع بسرعة، يعرف مبيعات اليوم، من عليه دين، متى يُعيد الطلب |
| الموظف/الكاشير | ينفذ مبيعات POS ويحصّل دفعات | شاشة بيع بثلاث خطوات، لا خيارات مربكة |
| المحاسب (اختياري) | يراجع القيود والتقارير | كل عملية لها أثر واضح قابل للتتبع |
| عميل المتجر الإلكتروني | يتصفح ويشتري ويتتبع طلبه | متجر سريع، Checkout بسيط، تتبع شفاف |
| مدير المنصة (Super Admin) | يدير المشتركين والإيرادات والصحة | لوحة تحكم تشغيلية، لا يعدّل أرقامًا مالية مباشرة |

## 4. فلسفة البساطة (Simple UX Philosophy)

1. **Complexity Budget** لكل شاشة: كل عنصر يبرر وجوده أو يُحذف.
2. **One Primary Action** لكل شاشة.
3. **Progressive Disclosure**: لا أقساط لمن لم يفعّلها، لا فروع لمن لديه فرع واحد، لا حقول ضريبة لمن لم يستخدمها.
4. **Search First** في القوائم الكبيرة.
5. العمليات اليومية قصيرة: بيع = منتج → دفع → تأكيد. تحصيل دين = عميل → مبلغ → تأكيد.
6. لا مصطلحات تقنية/محاسبية في واجهة التاجر.
7. نتيجة كل عملية مالية واحدة واضحة: SUCCESS / FAILED / PENDING SYNC مع مرجع.

## 5. رحلات المستخدم الأساسية (Core User Journeys)

### 5.1 رحلة التاجر — Onboarding (وفق المرجع البصري 02_Onboarding.png) — v3
خمس خطوات مرقّمة بشريط تقدّم (لا خطوة سادسة):
1. **ترحيب** ("مرحباً بك في دفتر" مع "تخطي") + **منتقي لغة الواجهة ظاهر فورًا على شاشة الترحيب** (العربية/English/Türkçe) — لغة الواجهة مستقلة تمامًا عن الدولة (R).
2. **إنشاء حساب** (الاسم الكامل، البريد، كلمة المرور، موافقة الشروط + رابط تسجيل الدخول).
3. **اسم ونوع النشاط** (بطاقات اختيار: متجر إلكتروني/خدمات رقمية/مأكولات ومشروبات/أخرى).
4. **الدولة والعملة ولغة المتجر** — 3 حقول بالضبط: الدولة، العملة الأساسية، **لغة المتجر (Store Language)** لغة الواجهة العامة للمتجر الإلكتروني للعملاء — **مستقلة عن لغة واجهة التاجر وعن الدولة**، وتُملأ افتراضيًا بـ`recommended_locale` من Country Pack وتبقى قابلة للتعديل لاحقًا من الإعدادات في أي وقت. ملاحظة دقيقة: "العملة الأساسية تُقفل بعد أول معاملة مالية؛ لغة المتجر يمكنك تغييرها متى شئت".
5. **رابط المتجر** (`{store_slug}.{PLATFORM_ROOT_DOMAIN}` مع فحص توفر فوري واقتراحات) → "ابدأ متجرك الآن". **ملاحظة:** `PLATFORM_ROOT_DOMAIN` إعداد على مستوى المنصة (Platform-level configuration) — الدومين الحقيقي لم يُعتمد بعد؛ الصور المرجعية تعرض ".daftr.sa" كمحتوى Mockup بصري فقط وليست متطلبًا، وتغيير الدومين لاحقًا لا يمس أي Business Logic.

ثم: أول منتج → أول عملية بيع. (GOLD-36 المحدّث + GOLD-49)

### 5.2 رحلة البيع اليومية (POS)
بحث/مسح باركود → إضافة للسلة → خصم اختياري → عميل اختياري → طريقة الدفع (نقدي/بطاقة/دين) → **إتمام البيع** → نجاح واضح + خيار إرسال الإيصال واتساب.

### 5.3 رحلة تحصيل دين
العملاء → عميل متأخر → تحصيل دفعة → مبلغ (Chips سريعة: 5,000 / 10,000 / كامل) → طريقة دفع → تسجيل الدفعة → رصيد محدث.

### 5.4 رحلة الأقساط
بيع بالتقسيط: مقدم + عدد أقساط → خطة تقسيط → متابعة "مستحق اليوم / متأخر" → تحصيل قسط → تنبيهات تلقائية.

### 5.5 رحلة المخزون
إضافة منتج (صورة، اسم، سعر، تكلفة، باركود، حد تنبيه) → تنبيه "مخزون منخفض" → إعادة توريد (Purchase) → جرد دوري.

### 5.6 رحلة المتجر الإلكتروني (عميل النهاية)
تصفح → قسم → منتج → أضف للسلة → Checkout (عنوان + دفع فقط) → تتبع الطلب مرحليًا → تواصل واتساب عند الحاجة.

### 5.7 رحلة الطلبات (التاجر)
إشعار طلب جديد → مراجعة → قبول/تجهيز → شحن → تسليم؛ أو إلغاء مع سبب واسترداد عند اللزوم.

### 5.8 رحلة واتساب
ربط الحساب → تفعيل رسائل تلقائية (ترحيب، طلب جديد، تحصيل دفعة) → إرسال كشف حساب → تقرير يومي عبر واتساب.

### 5.9 رحلة المساعد الذكي (AI)
**ثلاث مراحل مرئية**: تحدّث الآن (استماع) → مراجعة العملية (ما فهمه AI: عميل/منتج/كمية/سعر/مدفوع/متبقٍ) → تأكيد العملية → تم التنفيذ. AI لا ينفذ ماليًا دون تأكيد صريح.

### 5.10 رحلة Super Admin
لوحة تحكم المنصة: مشتركون، متاجر نشطة، إيرادات، صحة النظام، توزيع جغرافي، دعم، فوترة — كثافة أعلى مسموحة لكن منظمة.

## 6. المبادئ الحاكمة لكل رحلة

- لا نجاح زائف: لا Success قبل Commit الخادم في العمليات المالية.
- Offline مُصمَّم: كل عملية محلية لها حالة مفهومة (Synced/Pending/Failed/Needs attention).
- فشل واتساب/التحليلات لا يفشل البيع.
- Empty states حيّة مع CTA واضح.
- رسائل الخطأ تجيب: ماذا حدث؟ هل بياناتي محفوظة؟ ماذا أفعل الآن؟

# DAFTAR — WhatsApp Architecture / معمارية واتساب

## 1. المبدأ

WhatsApp **Core Communication Layer** وليس زر مشاركة (Master §54). يعمل **Event-driven** بالكامل: يستمع للأحداث الرسمية عبر Outbox و**لا يكتب Business Logic خاصًا به** (Master §55). فشله لا يفشل أي عملية أساسية (Master §56).

## 2. التكامل الرسمي

- التكامل عبر القناة الرسمية المدعومة (WhatsApp Business Platform/API). تفاصيل المزوّد والمصادقة تُحسم في Phase التنفيذي وتُسجَّل في Open Decisions — دون اختراع قدرات.
- الربط من شاشة "إعدادات واتساب": ربط حساب → عرض الرقم والحالة (متصل) → فصل واتساب (إجراء خطر بتأكيد).

## 3. الرسائل التلقائية (Event → Template → Queue)

| الحدث | الرسالة | افتراضي |
|---|---|---|
| sale.completed | إيصال/شكر بعد الشراء | قابل للتفعيل |
| order.placed / order.shipped | إشعار العميل بحالة الطلب | مفعّل |
| payment.recorded | "تم تسجيل دفعة X ر.س" | مفعّل |
| installment.due / late | تذكير دفعة مستحقة | مفعّل |
| customer.created | رسالة ترحيب | مفعّل |
| daily.summary | التقرير اليومي للتاجر (مبيعات/طلبات/عملاء) | مفعّل |

- كل رسالة تلقائية لها Toggle في "الرسائل التلقائية" (كما في الهوية البصرية) + رسالة مخصصة + قوالب جاهزة.
- **إرسال كشف حساب**: يدويًا من ملف العميل — اختيار العميل + الفترة + معاينة الرسالة قبل الإرسال (لا إرسال لعميل خاطئ — Master §133).

## 4. القوالب والتعريب

- WhatsAppTemplate لكل (key, locale) بمتغيرات موثقة ({customer_name}, {amount}…). المعاينة تُعرض قبل الحفظ.
- الرسائل تُرسل بلغة العميل/العمل وفق تفضيل موثّق.

## 5. الطابور والموثوقية

- Outbox → WhatsApp Worker → مزوّد الخدمة. حالات الرسالة: queued → sending → sent → delivered → read / failed → retry (backoff أسّي، N محاولات) → dead_lettered + **Alert** (Master §70).
- Idempotency بـScope صريح (U): `UNIQUE(business_id, idempotency_key)` على جدول `whatsapp_messages` — نوع العملية معروف من الجدول نفسه (لا Literal داخل UNIQUE؛ Data Model §17)؛ وأحداث الويبهوك الواردة تُطابَق عبر `(business_id, event_source, external_event_id)` — المكرر يُتجاهل بأمان.
- Delivery status يظهر للتاجر (✓✓) حيث يدعم المزوّد ذلك.

## 6. التفضيلات والخصوصية والحصص

- تفضيلات لكل عميل (استقبال/إيقاف) وإعدادات خصوصية للحساب ("من يمكنه مراسلتك").
- Quotas حسب الباقة عبر Entitlement Engine؛ بلوغ الحد = رسالة واضحة بلا فقدان (Master §121).
- لا رسائل تسويقية جماعية في النطاق الأول (تقييم لاحق — Risk Register).

## 7. الفشل والتتبع

- Sale ناجحة + WhatsApp Job فاشل = نتيجة واضحة: العملية تمت، الرسالة "ستُعاد" أو "فشلت — أعد المحاولة".
- كل رسالة مرتبطة بـ `business_transaction_id` للعملية الأم للتتبع الكامل.

## 8. الاختبارات

إعادة المحاولة، تكرار الويبهوك، انقطاع المزوّد أثناء البيع (البيع ينجح)، قوالب باللغات الثلاث، معاينة متغيرات، حدود الباقة، فصل الحساب أثناء وجود رسائل queued.

# DAFTAR — Design System / نظام التصميم

> مستخرج من الصور المرجعية العشر المعتمدة (**Official Visual Design North Star**). الهدف: الحفاظ على الشخصية البصرية، لا نسخ Pixel-for-Pixel. **ممنوع أي color/font/radius/shadow/spacing خارج Tokens** (Master §21). الشاشة الخارجة عن النظام تُرفض إلا بسبب موثّق وDesign Review.

## 1. الشخصية البصرية

Clean · Premium · Modern · Calm · Trustworthy · Fast · Professional · Human.
مساحات بيضاء واسعة، بطاقات راقية مستديرة، ظلال خفيفة جدًا، أيقونات موحدة، حركة مدروسة محدودة، لا ازدحام. **لا يجوز أن تبدو أي لوحة كـAdmin Template جاهز** (Master §20).

## 2. Color Tokens (من الصور رسميًا)

### 2.1 الأساسية (معتمدة من لوحة الألوان الظاهرة في الصور)

| Token | القيمة | الاستخدام |
|---|---|---|
| `color.primary` | `#2563EB` | الأزرق Premium: الأزرار الرئيسية، الروابط، العناصر النشطة، الشعار |
| `color.primary.light` | `#60A5FA` | التدرجات، الحالات الثانوية، رسوم |
| `color.bg` | `#F3F4F6` | خلفية الشاشات |
| `color.text.secondary` / `color.icon.muted` | `#9CA3AF` | النص الثانوي والأيقونات الخافتة |
| `color.text.primary` / `color.navy` | `#111827` | Navy عميق للعناوين والنص الأساسي |
| `color.surface` | `#FFFFFF` | البطاقات والأسطح |

### 2.2 التدرجات

- `gradient.hero`: من `#2563EB` إلى `#60A5FA` (بطاقة "مبيعات اليوم" الزرقاء البارزة، بانرات المتجر).

### 2.3 الدلالية (مستخرجة من badges الحالات في الصور)

| Token | الاستخدام |
|---|---|
| `color.success` (أخضر + خلفية خضراء فاتحة) | مدفوع، متوفر، تم البيع بنجاح، +12% |
| `color.danger` (أحمر + خلفية حمراء فاتحة) | غير مدفوع، متأخر، مخزون متبقٍ حرج، حذف |
| `color.warning` (كهرماني + خلفية فاتحة) | مستحق، ديون مستحقة، تنبيهات |
| `color.info` (أزرق فاتح + خلفية) | قيد التجهيز، معلومات، مستحق اليوم (highlight أزرق) |
| `color.whatsapp` (أخضر واتساب) | أزرار/أفعال واتساب فقط (إرسال كشف) — يُستخدم بحصرية |

قاعدة: كل Badge دلالي = نص ملوّن على خلفية فاتحة جدًا من نفس العائلة + Radius كامل (pill) — كما في الصور.

## 3. Typography

- **الخط العربي المعتمد: Tajawal** (ظاهر في الصور: "عصري · واضح · أنيق")، مرخّص (OFL) — أوزان Regular / Medium / Bold.
- الإنجليزية/التركية: خط Sans متوافق بنفس الروح (يُحسم في Phase 1 ضمن Open Decisions، مرشّح: Inter).

| Token | الحجم (mobile) | الوزن | الاستخدام |
|---|---|---|---|
| `text.display` | 32–40 | Bold | أرقام البطاقة الرئيسية (12,450 ر.س) |
| `text.h1` | 24 | Bold | عناوين الشاشات |
| `text.h2` | 18–20 | Bold | عناوين الأقسام ("إجراءات سريعة") |
| `text.body` | 15–16 | Regular | النصوص |
| `text.body.strong` | 15–16 | Medium/Bold | أسماء العملاء والمنتجات والمبالغ في القوائم |
| `text.caption` | 12–13 | Regular | النصوص الثانوية (#PRD-1024، "منذ 10 دقائق") |

- الأرقام المالية دائمًا Medium/Bold وبخط واضح؛ العملة تظهر بجوار الرقم بصغر نسبي.

## 4. Spacing / Grid / Radius / Elevation

- **Spacing scale (4pt):** `space.1=4 … space.6=24, space.8=32`؛ التباعد بين البطاقات 12–16، حواف الشاشة 16 (mobile).
- **Radius:** `radius.sm=8` (حقول صغيرة/chips)، `radius.md=12–14` (بطاقات القوائم)، `radius.lg=16–20` (البطاقات الكبيرة)، `radius.full` (pills، FAB، أزرار دائرية).
- **Elevation:** ظلال خفيفة جدًا: `shadow.card` = opacity ≤ 6%، blur واسع، بدون حدود قاسية؛ البطاقات قد تستغني عن الظل بحد `#F3F4F6` فاتح.

| List Item | صورة/أفاتار + عنوان strong + caption + مبلغ/حالة + شيفرون |

| Timeline | نقاط زمنية عمودية (تتبع الطلب) |
| Toggle | **DAFTAR premium switch** (W): هوية دفتر البصرية (pill بمسار رمادي فاتح وthumb أبيض بظل خفيف؛ المفعّل أزرق primary أو أخضر success حسب السياق الدلالي) مع **سلوك Android أصيل** — Jetpack Compose/Material semantics، أهداف لمس ≥48dp، وإتاحة قارئ الشاشة. في الويب: نفس الـToken بسلوك WAI-ARIA switch. الصور المرجعية على أجهزة iPhone هي مرجع **بصري** فقط: نستهدف Apple-level craftsmanship لا Apple UI cloning |
| Receipt Card | بطاقة إيصال بحواف مسننة (zigzag) كما في POS |
| Bottom Sheet | تحصيل دفعة/إضافة عنصر — مقبض علوي، radius علوي كبير |
| Dialogs | تأكيد مالي فقط عند الحاجة (Master §154)، عنوان واضح + نتيجة |
| Empty State | أيقونة خفيفة + جملة ودودة + CTA ("أضف أول عميل") |
| Success State | علامة ✓ خضراء كبيرة + رسالة + مرجع العملية (#1024) — كما في "تم البيع بنجاح" و"تمت العملية بنجاح" |

## 6. Motion

- مدة 150–250ms، easing قياسي (ease-out للدخول).
- نجاح العملية: micro-check animation خفيفة؛ تنقل: fade/slide قصير. لا Animations استعراضية أو بطيئة (Master §157).
- Android: Haptics مدروس لنجاح البيع/مسح باركود/تأكيد حرج فقط (Master §158).
- **قاعدة W (Android Native Premium):** كل المكوّنات تُبنى كـDAFTAR components فوق Jetpack Compose بسلوك Android أصيل (Ripple، elevation، back handling، dynamic sizing) — الشخصية البصرية من Tokens، والسلوك من المنصة. ممنوع استنساخ مكوّنات iOS حرفيًا.

### 6.1 Onboarding Pattern (X) — من المرجع البصري 02_Onboarding.png

- تدفق ترحيب مرقّم (01–05): **ترحيب (مع "تخطي" + منتقي لغة واجهة فوري) → إنشاء حساب → اسم ونوع النشاط → الدولة + العملة + لغة المتجر (3 حقول) → رابط المتجر**.
- منتقي لغة الواجهة: زر نصي صغير أعلى شاشة الترحيب (Segmented/Menu) — لغة الواجهة مستقلة عن الدولة المختارة.
- لغة المتجر (Store Language): select ثالث في خطوة الدولة/العملة بأيقونة لغة دائرية، افتراضي recommended_locale، وملاحظة: "يمكنك تغيير لغة المتجر لاحقًا متى شئت".
- شريط تقدّم علوي رفيع أزرق يمتلئ مع الخطوات؛ ترقيم دائري أسفل كل شاشة في المادة التسويقية.
- بطاقات اختيار نوع النشاط: Radio cards بأيقونة tonal + عنوان + وصف سطر واحد (متجر إلكتروني / خدمات رقمية / مأكولات ومشروبات / أخرى).
- اختيار الدولة/العملة: حقول-select بأيقونة علم/عملة دائرية + ملاحظة مطمئنة ("يمكنك تغيير الدولة والعملة لاحقًا من إعدادات المتجر") — **ملاحظة: العملة الأساسية ثابتة محاسبيًا بعد أول معاملة (Data Model §1)؛ الملاحظة في الواجهة يجب أن تكون دقيقة — تُعاد صياغتها عند التنفيذ لتشير لما هو قابل للتغيير فعلًا**.
- رابط المتجر: حقل مركّب `https:// [____] .{PLATFORM_ROOT_DOMAIN}` (الجزء الثابت يُقرأ من إعداد المنصة وقت التشغيل — الدومين الحقيقي لم يُعتمد؛ "daftr.sa" في الصورة محتوى Mockup فقط) + قائمة اقتراحات بفحص توفر فوري (✓ متاح أخضر).
- Primary CTA أزرق كامل العرض ("متابعة" / "ابدأ الآن" / "ابدأ متجرك الآن") + رابط ثانوي نصي ("لديك حساب بالفعل؟ تسجيل الدخول").
- شاشة الترحيب: رسم توضيحي أزرق فاتح (هاتف + أيقونات عائمة) + نقاط carousel.
- ملاحظة محتوى: الصورة تعرض "السعودية/ر.س" كمحتوى Mockup — الأسواق الأساسية المعتمدة تبقى PS/JO/LB/SY/TR (Master §27) والمحتوى التجريبي ليس مواصفة سوق.

## 7. Responsive

- **Mobile**: عمود واحد، bottom navigation، أهداف لمس ≥ 44px (Master §164).
- **Tablet**: نفس البنية بعرض أوسع؛ قوائم بعمودين عند الحاجة.
- **Desktop/Web (تاجر)**: Sidebar يمين (RTL) + محتوى ببطاقات، كثافة أعلى قليلًا لكن منظمة.
- **Super Admin**: Sidebar أعمق + KPIs + خرائط/رسوم — كثافة أعلى مسموحة للمستخدم المتخصص (Master §124).
- **Storefront**: نفس الهوية (أزرق/بطاقات/radius) — بانرات gradient، شبكة منتجات، Checkout خطواته واضحة؛ الأداء أولوية (LCP، صور محسّنة).

## 8. قواعد الاعتماد

1. كل Token يعرف باسمه في `packages/design-system` — لا قيم خام في الشاشات.
2. تباين النصوص الأساسية يحقق WCAG AA كحد أدنى (Master §162–163).
3. كل مكوّن يُختبر RTL وLTR وباللغات الثلاث قبل اعتماده.
4. الهوية تُراجع مقابل الصور المرجعية في **PREMIUM EXPERIENCE AUDIT** قبل الإطلاق (Master §168).

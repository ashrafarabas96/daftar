# DAFTAR — Localization Architecture / معمارية التعريب (v2)

## 1. اللغات من الدرجة الأولى

العربية، English، Türkçe — **لا لغة درجة ثانية** (Master §23). العربية Native RTL، والإنجليزية/التركية Native LTR (Master §26).

### 1.1 لغة المنصة مقابل لغة البلد (R) — محسوم

- **platform_supported_locales = [ar, en, tr]** ثابتة على مستوى المنصة ومتاحة لكل مستخدم **بصرف النظر عن Country Pack**.
- الحزمة القُطرية تحمل فقط `recommended_locale` و`recommended_storefront_locales` (اقتراحات Onboarding) — لا تمنع تاجرًا فلسطينيًا من استخدام Türkçe إن اختارها.
- **ثلاث لغات مستقلة في Onboarding (محسوم):** (1) **لغة واجهة التاجر** — منتقي فوري على شاشة الترحيب؛ (2) **لغة المتجر Store Language** — حقل ثالث في خطوة الدولة/العملة، افتراضيها `recommended_locale`، وتُعدَّل لاحقًا من الإعدادات في أي وقت؛ (3) **الدولة/العملة** — العملة الأساسية تُقفل بعد أول معاملة مالية (Data Model §1). لا علاقة سببية بين الثلاثة.

## 2. مستويات اللغة

| المستوى | الوصف |
|---|---|
| لغة واجهة المستخدم | يختارها المستخدم؛ افتراضيًا لغة الجهاز مع fallback لإعداد Business |
| لغة المتجر الإلكتروني | يحددها التاجر (قد تختلف عن واجهته)، مع إمكانية تعدد لغات الواجهة العامة حسب الباقة |
| لغة المحتوى | كبيانات: ProductTranslation + **CategoryTranslation** + **business_public_texts** (اسم/وصف المتجر العام، السياسات، تذييل الفاتورة) + نصوص حالات الطلبات المعروضة للعميل — كلها معرّبة كبيانات (Data Model §15) |
| لغة الرسائل | قوالب واتساب والإشعارات لكل locale |

## 3. إدارة الترجمات

- **Translation files** لكل لغة لكل تطبيق (web/android/storefront) بمفاتيح هرمية: `pos.checkout.complete_sale`.
- ممنوع نصوص ثابتة في الكود. ممنوع ظهور key للمستخدم.
- **Fallback**: ar ← en فقط كشبكة أمان تقنية، لكن **English fallback غير مقصود = عيب حاجب** في Localization Audit (Master §25).
- **Pluralization**: صيغ الجمع الكاملة (العربية 6 فئات CLDR، التركية/الإنجليزية حسب CLDR) — ممنوع تركيب "عدد: 5" الهروبي في الجمل الحساسة.

## 4. RTL/LTR

- لا flipping أعمى: كل Component يُختبر في الاتجاهين (Master §26).
- الأيقونات الدلالية الاتجاهية (أسهم، تقدّم، شيفرون) تعكس اتجاهها؛ الأيقونات المحايدة (ساعة، طابعة) لا تعكس.
- **Mixed-direction strings**: أرقام هواتف وأكواد SKU وأسماء لاتينية داخل نص عربي تُلفّ بعلامات bidi صحيحة (unicode bidi isolation) وتُختبر بصريًا.
- الأرقام: افتراضيًا Western Arabic (0-9) في كل اللغات للاتساق المالي، مع قابلية locale override موثّق.

## 5. التنسيقات (F) — مصحّح

- **الأموال والأرقام والتواريخ**: عبر **ICU / Intl / Unicode CLDR** حسب locale الواجهة — رمز العملة وموضعه والفواصل العشرية والآلاف تأتي من CLDR، **وليست خصائص مخزّنة للعملة أو البلد** (سجل العملات يحمل فقط: ISO code، minor_units، الأسماء).
- **التواريخ**: تقويم ميلادي افتراضيًا في كل الأسواق الأولى؛ مناطق زمنية لكل **Business**.
- الوحدات والقياسات حسب Country Pack، وتنسيق الكميات الكسرية حسب `unit_decimals` + CLDR.

## 6. بوابة الجودة اللغوية (Master §24)

أي ترجمة جديدة تمر على: المعنى → القواعد → الإملاء → سياق الواجهة → الطول (لا كسر للتخطيط) → RTL/LTR.

## 7. Translation Freeze (Master §25)

قبل كل Release يُنفَّذ **Localization Audit** آلي + بشري:
- لا Missing Translation (فحص آلي: كل المفاتيح موجودة في اللغات الثلاث).
- لا fallback غير مقصود، لا عربي/تركي مكسور، لا placeholder ظاهر.
- لقطات Visual Regression للشاشات الحرجة باللغات الثلاث والاتجاهين.

# DR-85 — a narrow, retroactive lane exception for P7-ANDROID in `.github/**`

**Decided by the owner, 2026-11-04.** Recorded in full in
`.local-context/OWNER_DECISIONS_AR.md` (DR-85) and summarised here because
`docs/decisions/**` is the tracked record (DR-24).

## The conflict this resolves

DR-66 authorises the P7-ANDROID lane for `apps/android/**` only, and names
`.github/**` as outside it. Card P7-01, authorised by that same DR-66, is
titled *promote the offline kernel into a Gradle module CI already builds* —
and CI did not build it, so the card could not be satisfied without touching
`.github/workflows/ci.yml`. An independent review found the contradiction and
it was escalated to the owner rather than resolved in the lane.

## The exception

Retroactive, and its list is **closed**. Anything not on it needs a new
decision.

| # | What | Why | Card |
|---|---|---|---|
| 1 | the `android` job in `ci.yml` | the module had no CI at all | P7-01 |
| 2 | the CI-VARIANT inventory gate | prints `139 == 139` against a statically computed inventory, not a written number | P7-01 |
| 3 | two narrow `.gitleaksignore` entries | UUID-shaped test fixtures renamed to `opId`; the entries are pinned by line digest, path and rule — never a blanket exemption | P7-GITLEAKS |
| 4 | the `red-proofs` job | the harness that 105 red proofs live in had never been executed | P7-01 |
| 5 | `docs/decisions/**` for P7 | this file and `2026-11-04-dr84-capture-digest-gate.md` | DR-84/85 |

lane's diff and belong to DR-86 and its own pull request.

## Item 4 in detail — what the `red-proofs` job is, and its negative control

Card P7-01's acceptance criterion is *N of N caught by name, against a floor
measured from the guard itself*. Half of it was met: the committed test counts
105 `Proof(` rows out of the harness source, reads its `102` literal, counts
100 static arm sites and says in words that 100 is a floor and not the verdict.
The other half was never met — nothing ran the harness. Measured: `red_proofs`
had zero mentions in `ci.yml`, with `runs-on` at 6 hits over 86,021 bytes as
the positive control, so that zero was a measurement and not an empty probe.

And it was an impossibility rather than an oversight. Five independent reasons
were measured, each found by trying:

1. there is no `offline-kernel/test` directory at all — `git ls-tree` lists
   exactly `.gitignore README.md build.gradle.kts src tools`;
2. the sources live at `src/main/java/...`, not at `src/...`;
3. `run-tests.sh` compiles `"$SRC"/app/daftar/offline/*.kt`, the pre-promotion
   layout;
4. all four tool files are committed `100644`, with no `755` among them, so
   `red-proofs.sh` cannot be exec'd;
5. `toolchain.sh` fetches with `--cacert /root/.ccr/ca-bundle.crt`, a local
   TLS-interception CA bundle that exists on no runner and is absent on the
   authoring host too — so that download had never been able to succeed
   anywhere. `git log -S` puts the line in `764671fd` (2026-10-07), the prep
   commit, so it is inherited and not introduced here.

None is repaired in place, because `tools/red_proofs.py`, `tools/run-tests.sh`,
`tools/red-proofs.sh` and `tools/toolchain.sh` are four of the 27 sha256-pinned
files whose bytes **are** the proof that P7-01 moved this module rather than
rewriting it. So the tree is shimmed outside the repository instead, the exec
bit is set on the copy only — modes are not what the pins hash — and the
toolchain is provisioned at the path the harness's own banner named, verified
against a digest pinned in `ci.yml` and against each publisher's own sidecar
read independently on the runner.

**No `continue-on-error`, and no raised limit.** `timeout-minutes: 120` on a
job that did not exist tightens GitHub's 360-minute default.

**The negative control, per DR-55.** The harness names `QueueModelCheckTest`
47 times — more than every other suite in it together — so it is the detector
most of the table depends on. The control copies the shim, neuters every
assertion in that suite, and **requires the job to fail**: a harness that still
reports all 105 proofs satisfied against a suite that can no longer go red is
not measuring the suite, and a green run above it would prove nothing. The
plant is proven applied by a changed sha256 **and** by counting zero live
assertion sites, because a substitution that matched nothing would otherwise
read as a passing control — which is worse than a failure, since it is read as
a measurement.

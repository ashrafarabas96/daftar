# DAFTAR — Backup & Disaster Recovery / النسخ الاحتياطي والتعافي

## 1. الاستراتيجية

| الأصل | الاستراتيجية |
|---|---|
| PostgreSQL | نسخ يومية كاملة + WAL archiving مستمر لـ**PITR** (point-in-time recovery) |
| Object Storage (صور/ملفات) | نسخ/versioning + تكرار إقليمي حيث متاح |
| Redis | لا بيانات حقيقة — إعادة بناء من المصدر |
| Config/Secrets | نسخ مشفّرة موثقة خارج النظام الأساسي |

## 2. الأهداف

- **RPO**: ≤ 15 دقيقة (WAL مستمر).
- **RTO**: ≤ 4 ساعات لاستعادة الخدمة الكاملة.
- **Retention**: يومي × 14، أسبوعي × 8، شهري × 12 — موثّقة ومشفّرة ومراقبة (Master §102).

## 3. قواعد ملزمة

1. **النسخة لا تُعدّ ناجحة دون Restore Test** (Master §103).
2. **Restore Drill دوري** (شهريًا كهدف) على بيئة منفصلة مع تحقق من: Database، Tenants (العزل)، Ledger (توازن القيود)، Inventory (مطابقة الحركات)، Files (Master §104).
3. تشفير كل النسخ + مفاتيح منفصلة + سجل وصول.
4. مراقبة نجاح/فشل النسخ مع تنبيهات — فشل Backup = Alert فوري، لا صمت (Master §70).
5. قبل أي Migration إنتاجية كبيرة: نسخة مؤكدة + Rollback plan (Master §112–113).

## 4. سيناريوهات التعافي الموثقة

| السيناريو | الإجراء المختصر |
|---|---|
| فقدان قاعدة البيانات | استعادة آخر Full + WAL حتى النقطة المطلوبة → تحقق → تبديل |
| تلف بيانات جزئي (خطأ برمجي) | PITR لنسخة جانبية → استخراج/مقارنة → Data Repair Tool رسمي (Dry Run + Audit) — لا تعديل يدوي مباشر (Master §147–148) |
| فقدان ملفات | استعادة من versioning → إعادة توليد variants من الأصول |
| كارثة إقليمية | خطة Failover موثّقة (تفاصيلها مع البنية التحتية في Phase التنفيذي) |

## 5. التحقق بعد أي استعادة

Checklist: عدّ السجلات الحرجة، توازن القيود (INV-ACC-01)، مطابقة المخزون (INV-INV-03)، عزل المستأجرين، Smoke Tests كاملة (Master §111).

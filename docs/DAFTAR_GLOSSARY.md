# DAFTAR — Glossary / قاموس المصطلحات الموحّد

> **قاعدة ملزمة:** يُمنع استخدام مصطلحين مختلفين لنفس المفهوم في الكود أو الواجهات أو الوثائق. أي مصطلح جديد يُضاف هنا أولًا قبل استخدامه.

## 1. مصطلحات الأعمال الأساسية

| المصطلح (EN) | العربية | التعريف الدقيق |
|---|---|---|
| Tenant | المستأجر / الحساب | الحد الأعلى لعزل البيانات. يمثل اشتراكًا واحدًا في المنصة. كل صف في الجداول التجارية يحمل `tenant_id`. |
| Business | النشاط التجاري | الكيان التجاري داخل Tenant (اسم، بلد، عملة أساسية). Tenant قد يحتوي Business واحدًا أو أكثر (حسب الباقة). |
| Branch | الفرع | موقع تشغيلي داخل Business (متجر، نقطة بيع). المبيعات والمخزون ترتبط بفرع. |
| Warehouse | المستودع | موقع تخزين مخزون. الفرع قد يرتبط بمستودع افتراضي. |
| User | المستخدم | شخص يسجل الدخول (مالك، موظف، مدير). |
| Role | الدور | مجموعة صلاحيات مسماة (Owner, Manager, Cashier…). |
| Permission | الصلاحية | قدرة ذرّية (sale.create, refund.approve…). |

## 2. المنتجات والمخزون

| المصطلح | العربية | التعريف |
|---|---|---|
| Product | المنتج | العنصر القابل للبيع (له SKU، سعر، تكلفة، تصنيف). |
| ProductVariant | متغيّر المنتج | نسخة من المنتج بخصائص مختلفة (لون/مقاس). كل Variant له SKU مستقل ومخزون مستقل. |
| Stock | المخزون | كمية منتج في موقع، **مشتقّة دائمًا من StockMovements**. |
| StockMovement | حركة مخزون | سجل لا يُحذف ولا يُعدَّل يصف تغيّر كمية (دخول/خروج) مع سبب ومصدر ومرجع ومستخدم ووقت. مصدر الحقيقة الوحيد للمخزون. |
| Reservation | الحجز | حجز مؤقت لكمية لصالح طلب/سلة، له صلاحية زمنية (TTL)، ويُحرَّر أو يُستنفد — لا يقلل المخزون الفعلي. |
| Stocktake | الجرد | عملية مطابقة عدّ فعلي مع المخزون الدفتري، تنتج Adjustment موثّقًا. |
| Adjustment | تسوية مخزون | حركة مخزون تصحيحية بسبب موثّق (تلف، فرق جرد…). |

## 3. المبيعات والطلبات

| المصطلح | العربية | التعريف |
|---|---|---|
| Sale | عملية بيع | حدث تجاري مكتمل داخل المنشأة (POS أو بيع يدوي). يُنتج Invoice ويؤثر على المخزون والمحاسبة. |
| Order | الطلب | طلب شراء من المتجر الإلكتروني. له دورة حياة (قيد المراجعة → التجهيز → الشحن → التسليم). عند القبول/التنفيذ يتحول إلى Sale. |
| Invoice | الفاتورة | الوثيقة المالية الرسمية لعملية بيع: البنود، الإجمالي، الخصم، الضريبة، المدفوع، المتبقي. |
| SaleItem / OrderItem | بند البيع / بند الطلب | سطر داخل الفاتورة/الطلب: منتج، كمية، سعر وحدة **تاريخي مجمّد**، خصم بند، ضريبة بند. |

## 4. الأموال

| المصطلح | العربية | التعريف |
|---|---|---|
| Payment | الدفعة / التحصيل | حركة أموال فعلية (نقد، بطاقة، تحويل). **مستقلة عن الإيراد** — تحصيل دين قديم لا يُنشئ إيرادًا جديدًا. |
| Receivable | ذمة مدينة / مستحق على عميل | المبلغ المستحق على عميل ناتج عن فاتورة غير مسددة بالكامل. يُشتق من Invoice + Payments ولا يُخزَّن كرقم يدوي. |
| Debt | الدين | العرض التجاري للـReceivable في واجهة التاجر ("عليه 700"). ليس نظام رصيد مستقلًا. |
| InstallmentPlan | خطة التقسيط | جدول دفعات لسداد Receivable واحد: مقدم + أقساط بتواريخ استحقاق. |
| Installment | القسط | دفعة مجدولة واحدة ضمن InstallmentPlan (مبلغ، تاريخ استحقاق، حالة). |
| Refund | الاسترداد | إرجاع مال للعميل من مصدر واحد صريح (Credit Note أو Customer Credit فقط — ليس Raw Payment). لا يتجاوز remaining المصدر بعملته أبدًا. |
| Customer Credit | رصيد العميل الدائن | التزام للعميل (2210) من overpayment أو عكس دفعة؛ يُصفّى بتخصيص على فاتورة أو Refund فقط — ليس إيرادًا. |
| reverse_payment_allocation | عكس تخصيص دفعة | أمر ذرّي يعيد فتح AR بالسنابشوت الأصلي ويحوّل المال (الباقي لدينا) إلى Customer Credit — لا يلمس Revenue ولا الأصل النقدي. |
| payment_reversal | إبطال تحصيل | أمر ذرّي لذهاب المال نفسه (chargeback/شيك مرتجع/تحويل معكوس): يعكس أصل النقد ويعيد فتح AR عند الحاجة — لا يلمس Revenue. مختلف جوهريًا عن عكس التخصيص. |
| Return | المرتجع | إرجاع بضاعة مباعة: يعكس المخزون والإيراد عبر قيد عكسي قابل للتتبع، **دون حذف العملية الأصلية**. |
| CreditNote | إشعار دائن | وثيقة تخفيض ذمة عميل (مرتجع على فاتورة آجلة أو تسوية). |
| Purchase | المشترى / فاتورة شراء | شراء بضاعة من مورّد: يزيد المخزون ويُنشئ Payable. |
| Payable | ذمة دائنة / مستحق للمورّد | ما يستحق للمورّد. |
| Expense | المصروف | مصروف تشغيلي (إيجار، كهرباء…) بقيد محاسبي كامل. |

## 5. المحاسبة

| المصطلح | العربية | التعريف |
|---|---|---|
| Ledger | دفتر الأستاذ | السجل المحاسبي المركزي الداخلي. |
| JournalEntry | قيد اليومية | رأس قيد محاسبي: تاريخ، مرجع، نوع حدث، وصف. |
| JournalLine | سطر قيد | سطر مدين/دائن على حساب معين. **مجموع المدين = مجموع الدائن إلزاميًا**. |
| Account | الحساب | عنصر في شجرة الحسابات (أصول، التزامات، إيرادات، مصروفات، حقوق ملكية). |
| Posting | الترحيل | تحويل حدث تجاري إلى JournalEntry متوازن عبر Posting Engine حتمي. |
| Void / Reversal | الإلغاء / القيد العكسي | إبطال عملية بقيد عكسي موثّق — لا حذف أبدًا للسجلات المالية المكتملة. |

## 6. المنصة

| المصطلح | العربية | التعريف |
|---|---|---|
| Subscription | الاشتراك | اشتراك Tenant في باقة (FREE/STARTER/PRO/BUSINESS). |
| Entitlement | الاستحقاق | قدرة/حد مفعّل للـTenant (عدد فروع، WhatsApp، AI…). يُدار عبر Entitlement Engine مركزي. |
| Outbox | صندوق الصادر | نمط تخزين الأحداث ضمن نفس الـ DB Transaction ثم نشرها غير المتزامن. |
| Business Transaction ID | معرّف العملية التجارية | معرّف موحّد يربط العملية عبر كل الأنظمة للتتبع. |
| Country Pack | الحزمة القُطرية | إعدادات بلد: عنوان، هاتف، ضريبة، عملة افتراضية — كإعدادات بيانات لا كود داخل Domains. |

## 7. قواعد الاستخدام

1. الكود يستخدم الأسماء الإنجليزية أعلاه حرفيًا.
2. واجهة المستخدم تستخدم العمود العربي (أو الترجمة المعتمدة في `DAFTAR_LOCALIZATION_GLOSSARY.md`).
3. **ممنوع** في واجهة التاجر: Journal Entry, Debit, Credit, Outbox, Tenant ID, Idempotency… (Master §7).
4. أي لبس بين "Debt" و"Receivable": الدين هو العرض، والـReceivable هو الأصل المالي — نفس الرقم، مصدر واحد.
